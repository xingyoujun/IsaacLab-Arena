## 叠碗旧失败诊断

旧记录：`outputs/harness/g2_stack_001/payload/raw/episodes_failed.hdf5`。
失败发生在第一次右手下降、闭爪之前。TCP 目标误差先为 19.87 mm，
两次修正后为 2.54 / 2.37 mm，超过原有 2 mm 阈值。
HDF5 显示，下降并非固定姿态直线：TCP 从 y=-0.2406 m 绕至约 -0.1683 m，
在第 149 帧开始明显推碗，闭爪前碗已水平移动最多 86.58 mm。
因此误差阈值不是根因；关节空间规划只约束目标位姿，接触接近阶段缺少路径约束，
且 source 整体从规划障碍物移除，使下降扫过碗的路径可以被执行。

新记录：`outputs/harness/g2_stack_recheck_20260927`，任务与原始数据审计通过，
1041 帧，右碗/左碗抬升 151.48 / 150.98 mm；右手闭爪前碗的最大水平位移
仅 0.260 mm。没有放宽 TCP 容差或成功判据，也没有修改配方；这反映当前轨迹对
实际初始状态/路径选择敏感，不能把一次成功当作旧问题已彻底修复。
三路视频与导出通过；整个 Harness preview 约 243 秒。

额外检查发现转运阶段存在 `arm_[rl]_link3/4/5` 与 `head_link3` 的碰撞球重叠。
离线复核实际关节和指令关节均可重现，并非仅跟踪滞后。
证据：`outputs/harness/g2_review_20260927/collision_probe.json`；第 340 帧头部相机
画面为同目录 `stack_transfer_head.png`。碰撞球提示不等同于已确认网格接触，
但必须阻止把该条宣称为无碰撞训练数据。当前任务审计没有把自碰撞提示作为失败门槛，
G2 embodiment 的 PhysX self collision 也未启用。

原生 Graph planner 离线对照也能返回通向上述重叠姿态的路径，末端关节误差为零。
证据：`outputs/harness/g2_review_20260927/native_self_collision_config.json`。
试探的 `enable_self_collision` 参数被此 Graph config 拒绝（`set_param=False`），
没有把它当作有效修复，也没有修改安装包。碰撞球存在并不证明规划器已正确约束它。

后续修复应先加入已规划路径与实际轨迹的自碰撞验收，再针对近物接近/提起加入
固定姿态、小步长或笛卡尔约束及物体扰动检查；不能扩大碰撞忽略列表或放宽误差。
本轮按用户的一次成功预览流程保留该条供审核，不继续稳定性尝试。
