## 接口与状态

- `data_engine.assets.interactions` 读取 `usdcraft.training_interactions` v1，
  校验 sidecar 的 USD SHA256、米/弧度和 wxyz 约定，检查 USD 内嵌信息、部件、关节和接触坐标。
- 抓取/操作点属于 **当前刚体 link**，经 `T_W_L(q) * T_L_G` 变换。
  不把 joint 的零位标注直接当世界坐标；接触 frame 不等于具体机器人的 flange frame。
- Pinch 宽度是米。超过 Robotiq 2F-85 的 85 mm 范围会报告不适配；不缩放资产。
- Latch 使用物理子步中的实测关节位置判断 release/re-engage；保持时收紧关节限位，
  释放时恢复原限位。原弹簧、阻尼、关节摩擦保留，不通过写位置制造弹开运动。
- 任务测试台明确固定 appliance 主体。热水壶 power_base 是单独的 rigid object，
  加入场景录制和 reset；这两个场景不用于验证提壶离座。
- 任务成功必须有锁住→释放的时序证据及稳定终态；按钮自己的默认 tolerance 不能替代解锁判据。
- 修正共享 cuMotion executor 的末采样浮点越界：最后一个目标严格取 trajectory.duration，避免原生 API 返回空状态；有针对性回归测试。
- HDF5 保存 7 维机器人动作、全部物体关节、壶底座状态；JSON 保存操作选择、锁扣事件和阶段。
  四路 RGB 当前是 post-step 预览，不授予 pre-action 训练或批量采集资格。

## 标注审计

21 个资产、71 个 interaction 通过首轮 USD/sidecar 一致性、frame、单位和关节校验。
这证明标注结构和 USD 相符，不证明 71 个操作均能由当前夹爪执行。

| 资产/操作 | 审计结论 |
|---|---|
| 五种 cube | 两侧 pinch 和 stacking/push 候选坐标一致；各任务仍须检查地面/邻物净空 |
| bar | 30 mm 侧面抓取可作为候选；120 mm 端面抓取超过 85 mm |

| button | 0–12 mm 行程和 press 轴一致；弹簧意味着应在按压期间判断，不要求松开后保持 |
| mug/bottle/sign/cylinder/sphere | frame、宽度、关节引用检查通过；手柄孔与指尖净空、滚动/倾倒任务仍需实际验证 |
| tray/box/v_support/wall/push_mat | 接收/支撑/抓取点有定义；receive 只是功能点，缺少可直接替代任务容器容积判据的区域信息 |
| kettle release | target=3 mm、tolerance=2 mm 可在 1 mm 就判成功，但锁扣需 2.4 mm；场景另验解锁和开盖 |
| toaster cancel | 同样的宽 tolerance 可提前判成功；锁扣实际释放阈值 2 mm |

旧 case 的 20 项任务目录与 19 个 P20 资产绑定保持对应。

不自动升级为已物理验证。G2 与 RR 的资产不在本次 extension 中，不替换其 payload。

## 责任边界澄清

资产侧确定物体机制：joint 行程、驱动/弹簧、锁定与释放阈值、联动关系及重新扣合条件。
通用运行时负责忠实执行资产规则；当前自定义 latch 元数据由 harness 运行时解释，
这不意味着规则的定义权属于具体任务。Data engine 不应为了完成任务改变资产的联动阈值。

Data engine 确定任务目标、机器人策略、成功判据、容差、稳定时间与数据资格。
例如热水壶任务检查解锁后开盖达到任务目标，烤面包机任务检查先锁定、再取消、最后弹回。
按钮压到某个位置既可能是动作目标，也可能触发物理机制，但不自动代表整个任务成功。
此前把按钮 target/tolerance 的提前通过风险归为“资产标注待修复”不准确：
风险在于任务层错误复用该提示；本轮任务实现已使用独立的联动时序验收。
