# 首版验收标准与扩展门槛

软件验收、任务资格、数据集发布是三个不同结论。代码测试通过不会自动授予后两者。
本文件描述实现应遵守的标准；当前实际通过项以 development.md 和每次 quality.json 为准。

| 检查层 | 通过条件 | 失败/未知如何处理 |
|---|---|---|
| 静态配置 | 已知 scenario、角色/资产引用完整、字节校验通过、输入身份固定 | 不启动 worker；报告缺失/变更项 |
| 执行生命周期 | 一次尝试、一份身份、受控退出、子进程失败保留、目标不覆盖 | 写失败状态，禁止自动伪造成功 |
| 原始转移 | 非空有限值、真实 action 语义、步前观测与初始/前一步状态一致 | 原始记录保留为诊断，不能标为训练通过 |
| 任务结果 | 在线成功且独立 raw 证据满足任务判据 | 与录制损坏分开；失败可供专用学习用途，但不能混为成功示范 |
| 图像 | 全解码帧数、尺寸、fps、来源和时间合同正确；关键视角人工查看 | post-step preview 不能当 pre-step；同长度视频不能自动证明来源 |
| 标注 | instance/actor/object 身份、区间、每步 ID 和事件一致 | 未标注为 unknown，不能编造阶段；损坏标注拒绝 |
| 回放 | 模式和误差明确，满足任务对接触/相机的容差 | bounded 不写 exact；精密任务需独立容差认可 |
| 设备 | 物理/碰撞/规划/渲染的实际 device 有证据，无禁止回退 | unknown 或 fallback 不授予严格 GPU 资格 |
| 人工审核 | 对指定配置版本的视角、布局、动作、标注有明确决定 | pending 时保持单次预览模式 |
| 随机化稳定性 | 用户批准后执行约定分布，记录所有尝试/拒绝/失败及覆盖 | 单次成功或仅变 seed 不算稳定性 |
| 数据集 | 选择规则、拆分、防泄漏、模态映射、转换来源和 loader 通过 | 不静默跳过失败 episode，不覆盖已有版本 |

## 首版的三种结果

- `preview_validated`：当前适配器的 raw/视频自动检查通过，供查看；人工审核仍可 pending。
- `collection_failed`：worker 未完成，日志与原生失败数据保留。不能从遗留 MP4 推断成功。
- `audit_failed`：worker 返回成功但管线证据校验失败。必须检查证据，不能以进程退出码覆盖质量结果。

首版只实现一次尝试和封存数据重审，不提供批量采集或半条仿真轨迹恢复。
通过标准是这些状态真实反映执行，而非要求所有任务在新机器上第一次都成功。

## 必须保留的反例

- 正确帧数但错误 raw 来源的视频；pre/post-step 错一帧；非法末行删除。
- 同样维度但不同关节顺序或夹爪单位的动作；未保存抽屉关节状态。
- 超时退出、worker 非零退出、目标目录已经存在、同时占用同一个 harness device lease。
- 原始文件或配置在封存后改变；旧 layout 审核套到新随机化范围。
- 任务失败但记录完整；任务成功但图像/标注损坏；CUDA 请求成功但存在 CPU fallback。

## 尚未具备的资格

当前跨家族集成不授予严格 CUDA、随机化稳定性、所有 200 项任务支持或全量训练数据发布资格。
这些状态有具体后续验收点，不能通过重命名 CLI 或把 unknown 改为 pass 获得。
