## 2. 资产标注：由用户补全，尚未实施

标注随物体存入 HF 的 `assets/<asset_id>/`，schema/解析器/校验代码进 Git。
机器人工具适配放到 embodiment 中；场景位姿、相机约束放到 scene/task 中。
以下为建议字段，不是当前已支持的输入格式。

| 层面 | 必需信息 |
|---|---|
| 身份与几何 | 稳定 asset_id、revision/hash、来源/许可、米制单位、轴约定、尺寸、依赖闭包 |
| 部件语义 | 稳定 part_id 到 USD prim/link 的映射；handle、rim、interior、button 等功能角色 |
| 功能坐标系 | 前向、开启方向、支撑平面、放置区域、容器内部有效体积与开口 |
| 关节功能 | 父子 link、轴/原点、限位、零位、开合状态、可驱动部位、弹簧/阻尼/力模型 |
| 抓取 | 多个候选/连续抓取区域、所属 link、局部位姿、接近/撤离方向、预抓取距离 |
| 接触约束 | 接触面/patch、法向、禁抓区域、所需夹口宽度区间、指尖厚度/插入净空、夹持力范围 |
| 状态适用性 | 候选适用的关节状态、允许对称旋转、允许误差、任务模式及候选优先级 |
| 物理 | 质量、质心、惯量及来源；接触摩擦、阻尼、碰撞近似与误差、固定/自由安装条件 |
| 视觉 | 正确尺度/纹理/法线/材质；功能关键点与可见区域；外观变化不破坏任务语义 |
| 验证 | 验证使用的机器人/夹爪、仿真版本、配置、种子、成功数/总尝试数、失败证据 |

不要只给世界坐标的单个 TCP 姿态。采用 `T_L_G` 表示抓取功能坐标系 G 到部件 L 的
变换，`T_W_L(q)` 为当前关节状态下部件到世界的变换；机器人适配提供 `T_G_TCP`：

`T_W_TCP = T_W_L(q) * T_L_G * T_G_TCP`

明确位置单位、四元数顺序、G 的接近轴与闭合轴。接近轴需说明是朝接触点还是离开接触点。
带把手的关节物体应绑定运动 link，不能只绑柜体根坐标。夹口宽度用米，
由机器人适配器转换成夹爪关节值。通用接触区域和夹爪特定验证结果分别保存。
先检查几何/夹口适配，再做 IK、自碰撞、世界碰撞、接近路径和物理抓取验证。

抓取标注是候选和约束，不能代替运行时规划。推、按、插入、倾倒任务还需要对应的
接触方向、作用点、插入轴/容差、容器容量等 affordance，不能强行统一成 grasp。

## 3. Training-ready 标准：由用户推进，尚未认证

| 等级 | 通过条件 |
|---|---|
| sim-ready | 能可靠加载；尺寸/关节/碰撞有效；在规定安装条件下完成基础物理检查 |
| interaction-ready | 功能与接触标注完整；指定工具完成抓、放、推或驱动等物理验证 |
| task-ready | 在某机器人、场景、任务与参数范围内通过可见性、可达性、安全和成功条件验收 |
| training-ready | 上述证据齐全，加上经批准的随机化覆盖、稳定性验证、数据时序/动作语义/标注校验和可复现版本 |

不建议给资产一个无条件的 training_ready=true。应签发绑定
`asset revision × embodiment/tool × task × scene/cameras × randomization domain × simulator/profile`
的验证记录；更换碰撞模型、尺寸或机器人后相关证据失效，需要重新资格验证。
资产可以具备 training-ready 所需信息，但最终训练可用性属于资产与使用配置的组合。
稳定性合格标准应预先确定样本数量、随机分布、成功率/置信要求，不能用一条成功代替。


本轮没有修改/上传资产，没有提交或推送 Git，没有开展稳定性批量采集。
